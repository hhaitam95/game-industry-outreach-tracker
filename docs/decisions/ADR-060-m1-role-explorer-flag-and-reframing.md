# ADR-060 — M1 feature flag and product reframing

- **Date:** 2026-10-29
- **Status:** Design and definition of done recorded before implementation.
- **Goal:** Make the public-facing product consistently about finding official routes that explicitly accept speculative applications, not a standard vacancy or role explorer.
- **Scope:** Add one frontend feature-config module with `FEATURES.roleExplorer = false`; conditionally hide the legacy role explorer, all Overview role/opportunity counts and associated role-listing copy, and generic career-route links that could be mistaken for accepted speculative applications. Rename the existing directory navigation label to `Speculative applications`. Keep the underlying role components, parsing/filtering logic, schemas, data and tests in the repository.
- **Product wording:** Reframe the README opening, Overview copy, and the top-level project specifications, architecture and implementation plan. Clearly state that a general careers page or a current advertised role is not evidence of a speculative-application route. Until the evidence-backed route model and researched entries arrive in later milestones, do not imply any current profile has a verified speculative route.
- **Feature contract:** The sole default config is `src/config/features.mjs`, exporting an immutable `FEATURES` object whose `roleExplorer` value is `false`. UI components consume that config; a narrow injectable config parameter supports deterministic on/off component tests without changing the shipped default.
- **Compatibility:** Keep internal page IDs and existing component/API code stable for existing tests and future reuse. Do not delete legacy role code or rewrite the private-workspace schema in M1.
- **Automation boundary:** Discovery and Pages workflows remain manual-only. No workflow, schedule, publication, repository visibility, permissions, secret or dependency changes are in scope.
- **Failure behavior:** Missing or false configuration fails closed and hides legacy role UI. Enabling the feature in a test must restore the legacy UI deterministically; the production default remains off. Generic careers routes must not be represented as proof of speculative acceptance.
- **Tests:** Add tests proving the config default is false, both injected flag states work, the default Overview has no legacy role counts, and the directory view does not render the role explorer or generic-career-route claims when disabled. Keep existing role-explorer tests and add enabled-state regression assertions. Run formatting, lint, typecheck, unit/component tests, dependency audit, build/privacy/artifact checks and browser acceptance on the exact PR head.
- **Documentation:** Update README opening/product goals, Overview copy, PROJECT_SPECS.md, ARCHITECTURE.md, IMPLEMENTATION_PLAN.md, and the milestone changelog fragment. Keep volatile branch/PR/check state in STATUS.md only.
- **Definition of done:** With the default flag off, navigation reads “Speculative applications”; Overview contains no role-listing counts or legacy role-explorer wording; the role explorer and generic career-route claims are not rendered; tests cover both flag states; project copy matches ADR-059; no legacy code/tests are deleted; all required CI checks pass on the final M1 PR head.
- **Rollback:** Revert the M1 feature/config/UI/documentation changes as one reviewed PR while leaving the M0 refocus ADR and the existing legacy components intact.
