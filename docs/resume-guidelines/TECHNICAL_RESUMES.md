# Technical Resume Guidance

**Last reviewed:** 2026-10-24

This guidance supports technical support, developer support, tooling, build/release, technical QA, live-service operations, platform/DevOps and adjacent roles. It must be applied only where the candidate's experience supports the claim.

## Evidence before keywords

- Describe what the candidate actually investigated, built, automated, configured, tested, documented or coordinated.
- Connect tools to the problem or workflow in which they were used; a list of technologies without context is weaker evidence.
- Prefer concrete scope and outcomes where known (system type, issue category, workflow improved, stakeholders supported). Never fabricate counts, percentages, impact, scale or ownership.
- Clearly distinguish professional experience, personal projects, training, coursework and areas the candidate is learning.
- Do not imply professional game-development, game-engine, QA or build-engineering experience simply because it is a target role.

## Potential evidence patterns by role family

These are prompts for finding truthful examples, not claims to add automatically.

- Software/application support: troubleshooting complexity, incident diagnosis, reproduction, logs, APIs, integrations, SQL, customer/engineering coordination, documentation.
- Developer support/experience: enabling engineers, diagnosing tool/API issues, internal documentation, workflow friction, developer feedback and automation.
- Tooling support/internal tools: scripts, workflow automation, data transformations, maintainability, user feedback, adoption evidence if known.
- Build/release: CI/CD troubleshooting, deployment support, build failure analysis, version-control practices, release coordination; mark gaps such as Perforce or large build systems when absent.
- Technical QA/automation: reproducibility, structured test cases, bug reports, regression thinking, test scripts and debugging; do not claim QA employment unless true.
- Live/online services: incident response, logs/metrics, API/service behavior, escalation, operational handover and reliability work.
- DevOps/platform: automation, cloud environments, deployment workflows, containers and infrastructure; match the seniority and hands-on depth honestly.
- Integration engineering: API contracts, data discrepancies, file transfer, authentication/integration troubleshooting and cross-team diagnosis.

## Bullet-quality heuristic

A useful bullet often combines:
- Action: what the candidate did.
- Technical/context detail: which system, workflow, failure mode or tools were relevant.
- Purpose/result: what it enabled or improved, where supported by evidence.

Avoid inventing a metric just to make a bullet appear quantified. If a result is unknown, describe the verified task/scope plainly and recommend gathering evidence rather than fabricating an outcome.

## Tailoring

- Identify required and preferred skills separately.
- Put the strongest relevant evidence near the top.
- Use exact job-description terms only when they accurately describe candidate experience.
- Explain transferable skills and gaps without concealing them.
- Do not include every job keyword; relevance, evidence and readability matter more than keyword volume.
